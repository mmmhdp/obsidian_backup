# Функторы и состояние
## Обсуждение: `for each`
У нас есть метод `equal_range` в `unordered_multimap`, который возвращает диапазон пар ключ-значение с одинаковым ключом.
```cpp
std::unordered_multimap<int, int> m;
....
auto [begin, end] = m.equal_range(i);
```
Вы можете как-то проитерироваться и что-то сделать с каждым значением:
```cpp
for (auto it = begin; it != end; ++it) f(*it); // 1
std::for_each(begin, end, f); // 2
```
Какой из двух вариантов вы выберете и почему?
## Обсуждение
Выбирать всегда следует алгоритм стандартной библиотеки.
- Аргумент от тела цикла:
```cpp
for (auto elt : cont) {
	// позволяет неконтролируемо добавить сюда 
	// массу кода, скорее всего лишнего
}
```
- Аргумент от распараллеливания(`С++17`):
```cpp
for_each(
	std::execution::par, cont.begin(), cont.end(), func
);
```

В общем случае абстракция циклов повышает и читаемость и эффективность кода. Такого рода абстракции называются **абстракциями с отрицательной стоимостью**.
## Обсуждение
Представим, что нам надо как-то использовать внешнее значение.
Например, пусть нам надо умножить `value` на некоторое число:
```cpp
int mult = get_my_mult(); // очень долгая функция
for (auto it = begin; it != end; ++it)
	it->second *= mult;
```

Кажется, что тут нет способа сделать вызов `std::for_each`?
```cpp
int mult = get_my_mult(); // очень долгая функция
std::for_each(std::execution::par, begin, end,
	[](auto &&elt){elt.second *= mult}; // ошибка
) 
```
## Идея функтора
Допустим, мы написали класс с состоянием и оператором вызова:
```cpp
struct Multer {
	int m;
	Multer (int mult) : m(mult) {}
	void operator () (auto &&elt) {elt.second *= m;}
};
```
Тогда становится возможным следующее:
```cpp
int mult = get_my_mult(); // очень долгая функция
std::for_each(std::execution::par, begin, end, 
	Multer{mult});) 
```
Но на каждый чих не наздравствуешься.
Неудобно каждый раз писать функтор.
Делать это нам помогают возможности захвата переменных в лямбдах.
## Hello, lambda world
Давайте посмотрим на лямбды в блеске и славе:
```cpp
int main(int argc, const char **argv) {
	return [argv] () -> int {
		std::cout << "Hello from:" << argv[0] << std::endl;
		return 0;
	} ();
}
```
Мы можем это упростить, выкинув пустое тело и выводимый тип:
```cpp
int main(int argc, const char **argv) {
	return [argv] {
		std::cout << "Hello from:" << argv[0] << std::endl;
		return 0;
	};
}
```
Или так:
```cpp
hi = [argv] () {
	std::cout << "Hello from:" << argv[0] << std::endl;
	return 0;
};

hi();
```
## Обсуждение
Лямбда-выражения - это не функции:
```cpp
auto t = [k = z] (auto x, auto y) { return x < y  * k ;};
```
Это скорее классы с перегруженным `operator()`:
```cpp
struct __closure_type_for_t {
	int __k;
	auto operator() (auto x, auto y) const {
		return x < y * __k;	
	}
};

__closure_type_for_t t{z};
```
## Убираем `const`
Если мы хотим изменять захваченный по значению контекст мы должны сделать нашу лямбду в явном виде `mutable`:
```cpp
auto t = [z](auto x, auto y) mutable {
	z += 1; return x < y * z;
};
```
Обратите внимание, что `z` меняется в пределах замыкания:
```cpp
auto s = t;
t(1, 2); // z изменилось внутри t, но не внутри s;
```
Замыкания по умолчанию копируемые (если не захвачено ничего со стёртым `copy ctor`).
Глобальные и статические переменные захватывать не нужно, они доступны и так.
## Виды захвата
Захват по значению (по ссылке):
```cpp
auto fval = [a, b](int x) {return a + b * x;};
auto fvalm = [a, b](int x) mutable { a += b * x; return a;};
auto fref = [&a, &b](int x) { a += b * x; return a;};
```
Захват по ссылке всегда `mutable` и отслеживает состояние переменной:
```cpp
a = 42;
fval(x); // тот же
fref(x); // использует новое a
```
Разумеется, можно смешивать:
```cpp
[&a, b, &c, d] { a += c * b; c+=d; return a+c};
```
Захват всего контекста по значению(по ссылке):
```cpp
auto faval = [=](int x) {return a + b * x;};
auto fаref = [&](int x) { a += b * x; return a;};
```
Захват всего по значению и частично по ссылке и наобарот:
```cpp
auto favalb = [=, &b](int x) {return a + b * x;};
auto fаrefa = [&, a](int x) { b += a * x; return b;};
```
Захват с переименованием:
```cpp
auto freval = [la = a](int x) {return la + x;};
auto freref = [&la = a](int x) { la += x; return la;};
```
Захват с переименованием позволяет захватить правую ссылку:
```cpp
std::ostream_iterator<int> os {std::cout, " "};
std::vector v = {1, 2, 3};

auto out = [w = std::move(v), os] {
	std::copy(w.begin(), w.end(), os);
};
```
Теперь вектор передан в состояние замыкания.
Передача осуществляется в контсрукторе замыкания, т.е. в момент создания функции, а не в момент её вызова.
Т.е. список захвата выполнится именно в месте создания объекта замыкания, а не в месте вызова.

## Захват в теле класса
```cpp
struct Foo {
	int x;
	void func (){
		[x] mutable { x+= 3; } (); // FAIL
		[&x] { x+= 3; } (); // FAIL
		
		[=] { x+= 3; } (); // OK, but depricated in C++20
		[&] { x+= 3; } (); // OK, the right way to catch
		
		[this] { x+= 3; } (); // OK
	}
};
```
Это всё работает потому, что захват всего захватывает и `this`.
## Локальный контекст
```cpp
auto factory (int parameter){
	static int a = 0;
	return [=](int argument){
		static int b = 0;
		a += parameter;
		b += argument;
		return a + b;	
	};
}

auto func1 = factory(1);
auto func2 = factory(2);

cout << func1(20) << " " << func1(30) << " "
	 << func2(20) << " " << func2(30) << std::endl;
```
Определение класса замыкания - одно, т.е. `a` и `b` будут общими.
`a` как для фунции `factory`, а `b` как статическая переменная для перегруженного `operator()` внутри замыкания.

## Единая типизация замыканий
```cpp
auto t = [&x, &y] {return x + y;}
```
Тут не вполне ясно, а что такое `auto`...
Мало того, так нельзя делать в теле класса:
```cpp
struct Foo {
	auto t = [&x, &y] {return x + y;} // ошибка
};
```
Мы понимаем, что это `closure type`, но не можем записать его явно.
В этом случае, мы можем частично стереть тип.
