## Ограничения
Операторы (\*) и (->) обязаны быть методами, они не могут 
быть свободными функциями, как и оператор равно (=).

Интересно, что это не относится к разыменованию с обращением

# Index operator (`[]`)
```cpp
class MyVector {
	std::vector<int> v_;
public:
	int& operator[](int x) {return v_[x];}
	const int& operator[](int x) const {return v_[x];}
};
```

Но возникает некий вопрос, а что делать с ситуацией, когда мы хотим использовать 
синтаксис с несколькими скобками, как в матрице?

Идея - не возвращать указатель, ведь тогда мы раскроем внутреннее состояния, которое
так ревностно охраняем, а использовать класс-обёртку, у которого также будет перегружен операратор {}
```cpp
template <typename T> Matrix {
	//staff
public:
	//methods
	??? operator[] (int idx) const;
};
```
## Proxy-objects
```cpp
template <typename T> Matrix {
	// staff
	struct ProxyRow {
		T* row;
		T& operator[](int idx)  {return row[idx];}
		const T& operator[](int idx) const {return row[idx];}
	};
public:
	// methods
	// И тут мы бы уже и хотели использовать m[x][y]
	ProxyRow operator[] (int idx);
	const ProxyRow operator[] (int idx) const;
};
```
# Functor operator (`()`)
Наиболее правильный способ сделать функции-подобный объект - это перегрузка оператора ().
Данная история позволяет не просто передавать указатель на функцию, а как бы добавить к этому указателю информацию о типах в этой функции, что в свою очередь может позволить компилятору заинлайнить функцию, а не тратить ресурсы на её вызов.

```cpp
struct gt 
{
	bool operator() (int x, int y) {return x > y;}
};

/*
	и тогда далее мы можем передать этот объект вместо функции,
	например, в алгоритмы стандартной библиотеки
*/

std::sort (myarr.begin(), myarr.end(), gt{});
```
Кроме того, в классе можно хранить состояние.
Данная идея ещё получит своё продолжение в контексте lambda-функций.
# Increment and decrement operators(`++` and `--`)
Post и pre инкремент используют один и тот же оператор,
но для post добавляют dummy параметр int, так как по 
возвращаемому значеную нельзя перегрузить функцию:
```cpp
//pre
Quat<T>& Quat<T>::operator++();
//post
Quat<T> Quat<T>::operator++(int);
```

Обычно, постинкремент делается в терминах преинкремента:
```cpp
template <typename T> struct Quat 
{
	T x_, y_, z_, w_;
	Quat<T>& operator++() {
		x_+= 1; 
		return *this;	
	}
	
	Quat<T> operator++(int)
	// dummy parametr since overloading 
	// set is not change in terms of 
	// return value type
	{
		Quat<T> tmp {*this};
		++(*this);
		return tmp;	
	}
};
```
Очевидно, что всё тоже самое работает для декримента.

# Spaceship operator(`<=>`)
Доступен с 20 стандарта.

Определяет тривалентное сравнение [[Operators and chains#Дву и три валентные сравнения]]. Но он возвращает не int, а некий ordering_type

Если его перегрузить, то все остальные операторы сравнения будут сгенерированы в его терминах автоматически.
Ну или почти все, так как в данном случае не определится 
равенство(\=\=) и неравенство (!=) (потому что компилятор не сможет решить,
равенство в каком смысле нас интересует [[Operators and chains#Равенство и эквивалентность]]).
```cpp
struct MyInt {
	int x_;
	MyInt(int x = 0) : x_(x) {}
	std::strong_ordering operator<=>(const MyInt& rhs)
	{
		return x_ <=> rhs.x_;
	}
};
```
## Типы упорядочивания
| Тип упорядочивания<br> | Равные значения | Несравнимые значения |
| ---------------------- | --------------- | -------------------- |
| std::strong_ordering   | Неразличимы     | Невозможны           |
| std::weak_ordering<br> | Различимы       | Невозможны           |
| std::partial_ordering  | Различимы       | Возможны             |
- strong_ordering - это такой себе ordering в стиле int
- partial_ordering - это такой себе ordering уже в стиле float

## Defaulted spaceship operator
Тарелка это один из немногих примеров осмысленного умолчания
```cpp
struct MyInt {
	int x_;
	MyInt(int x = 0) : x_(x) {}
	auto operator<=>(const MyInt& rhs) = default;
};
```
Сгенерированный по умолчанию (изо всех полей класса) он сам определяет
упорядочение и как бонус определяет также равенство и неравенство

Логика тут такая: если вы генерируете всё по умолчанию, то вы 
точно не хотите от равенства ничего необычного

# Address extraction operator(`&`) 
Тоже может быть перегружено, как разыменовывание.
В реальности, перегружается редко.

```cpp
template <typename T>
class scoped_ptr 
{
	T *ptr;
public:
	scoped_ptr(T *ptr) : ptr(ptr) {}
	~scoped_ptr() {delete ptr;}
	T** operator&() {return &ptr;}
	T operator*() {return *ptr;}
	T* operator->() {return ptr;}
};
```

Опять же, в общем случае, если мы хотим взять адрес в обобщенном коде, мы не уверены, что operator& не перегружен. 

Поэтому, необходимо в таких случаях использовать addressoff:
```cpp
std::addressof(obj);
```
Он вернёт именно что адрес объекта, который ему был передан.

## Указатели на метод класса
Имеет ли смысл выражение "указатель на нестатический метод"?
```cpp
struct MyClass 
{
	int DoIt(float a, int b) const;
};
```
Казалось бы, что нет.

Как мы уже говорили, метод частично ведёт себя как будто это функция вроде:
```cpp
int DoIt(MyClass const *this, float a, int b) const;
```

И на такую функцию возможен указатель.
Но метод класса не является этой функцией.

Например в точке вызова на него должны распространяться соображения
времени жизни и контроля доступа.
**Вызов через подобный указатель на функцию кажется возможностью нарушить инкапсуляцию**.

Повторим вопрос.
Имеет ли смысл выражение "указатель на нестатический метод"?
На удивление, да, имеет.
```cpp
using constif_t = int (MyClass::*) (float, int) const;
```

И поддерживается два синтаксиса:
```cpp
constif_t ptr = &MyClass::DoIt;
MyClass c; // необходим для создания контекста (this нужен)
(c.*ptr) (1.0, 1);

MyClass *pc = &c; 
(pc->*ptr)(1.0, 1);
```

НО, (.\*) не перегружается и (::\*) также не перегружается.

Оператор (->\*) примечателен своим никаким грамматическим 
приоритетом и никакими требованиями к перегрузке.

Как следствие, он выступает в роли запасного оператора, который 
перегружают для совершенно разных нужд. 
НО ДЕЛАТЬ ТАК НАДО В ПОСЛЕДНЮЮ ОЧЕРЕДЬ!

Вот немного безумный пример:
```cpp
template <typename T>
T& operator->*(pair<T, T>& l, bool r)
{
	return r ? l.second : l.first;
}

pair <int, int> y {5, 6};
y ->* false = 7;
```


# Sequence operator (`,`)
```cpp
result = foo(), bar(), buzz();
// foo() guaranteed to be called first
// result =  buzz();
```
И он тоже перегружаемый.
Никогда не стоит его перегружать, так как тогда теряется 
тот самый sequencing (отношение последования [[Sequecing]]), а это того не стоит никогда.


# Что нельзя перегрузить
- Доступ через точку a.b
- Доступ к члену класса через точку a.\*b
- Доступ к пространству имён a::b
- Последовательный доступ a ; b
- Тернарный оператор a ? b : c
- Почти все специальные операторы в том числе
  `sizeof`, `alignof`, `typeid`
  - Правило такое: если вы видите специальный оператор,
    скорее всего его нельзя перегрузить
	(исключения: `new`, `delete`, `co_await`)
  - Сюда же относятся `static_cast` и его друзья (`*_cast`)
# Что не следует перегружать
- Длинный логические операции `&&` и `||` потому что они 
  теряют сокращенное (`lazy`) поведение
```cpp
if (p && p->x) // может рвануть при перегрузке &&
```
- Запятую, чтобы не потерять `sequencing`
```cpp
x = foo(), bar(); // взрыв, если мы заложились на foo первым
```
- Унарный плюс, чтобы не потерять `positive hack`
