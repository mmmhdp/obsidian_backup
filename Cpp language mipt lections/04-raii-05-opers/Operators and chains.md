# Ваши типы как встроенные
Собственный класс кватернионов
```cpp
template <typename T> struct Quat {
	T x, y, z, w;
};
```
У нас уже есть бесплатное копирование и присваивание.
Хотелось бы, чтобы работало и всё остальное: сложение, умножение и т.д.

Начнём с чего-нибудь простого:
```cpp
Quat q {1,2,3,4};
Quat p = -q; // унарный минус: {-1,-2,-3,-4}
```
# Общий синтаксис операторов
Обычно используется запись operator и далее какой это оператор
```cpp
template <typename T>
struct Quat 
{
	T x, y, z, w;
};

template <typename T>
struct Quat<T> operator-(Quat<T> arg)
{
	return Quat<T>{-arg.x, -arg.y, -arg.z, -arg.w};
}

// Теперь всё как надо и это работает
Quat q {1,2,3,4};
Quat p = -q; // унарный минус: {-1,-2,-3,-4
```
Альтернативный вариант - это метод в классе
```cpp
template <typename T>
struct Quat 
{
	T x, y, z, w;
	Quat operator-() const 
	{
		return Quat(-x, -y, -z, -w);
	}
};

// И это тоже работает как надо
Quat q {1,2,3,4};
Quat p = -q; // унарный минус: {-1,-2,-3,-4}
```

Т.е. обычно для определения того или иного оператора
есть два варианта (исключение это присваивание и пара-тройка других):
```cpp
-a означает a.operator-(); // def in class
-a означает operator-(a);  // def out of class
```
Важно - если определены оба варианта, то перегрузку всегда выиграет вариант, который определён внутри класса.
Логика простая - внутри класса - значит писал разработчик класса, который в курсе его инвариантов, а определенный снаружи - ну как бы второй порядок доверия.


# Цепочечные операторы 
Операторы, образующие цепочки имеют вид op=
```cpp
int a = 3, b = 4, c = 5;

a += b *= c -= 1;
```
- Все они правоассоциативны.

- Исключения составляют очевидные бинарный операторы <= и >=.

- Все они модифицируют свою правую часть и их место внутри класса в качестве его методов 
```cpp
struct Quat {
	int x, y, z, w;
	Quat& operator+=(const Quat& rhs) {
		x += rhs.x, y += rhs.y, z += rhs.z, w += rhs.w;
		return *this;
	}
};
```
Тут возврат ссылки на себя необходим для поддержания цепочки:
```cpp
a += b *= c; // a.operator+=(b.operator*=(c));
```

А далее ещё раз обратимся к этому сильному приёму - определение одного метода или перегрузки оператора в терминах другого_ой.
Так мы можем переопределить оператор +, в терминах оператора +=:
```cpp
struct Quat {
	int x, y, z, w;
	
	Quat& operator+=(const Quat& rhs) 
	{
		x += rhs.x, y += rhs.y, z += rhs.z, w += rhs.w;
		return *this;
	}
	
	Quat operator+(const Quat& rhs) const
	{
		Quat tmp {*this};
		tmp += rhs;
		return tmp;
	}
};
```

# Сигнатуры операторов
Сигнатура должна совпадать с точностью до количества аргументов.

У бинарного оператора это:
```cpp
a.operatorX (b)
operatorX (a, b)
```

У оператора присваивания и некоторых других есть только первая форма.

С точки зрения языка и оператор + и оператор += это независимые бинарные операторы. По сути, просто разные методы.
# Сравнения как бинарные операторы
Есть два подхода к определению равенства:
```cpp
template <typename T>
bool operator== (const Quat& lhs, const Quat& rhs)
{
	return (&lhs == &rhs);
}

template <typename T>
bool operator== (const Quat& lhs, const Quat& rhs)
{
	return (lhs.x == rhs.x) && 
	(lhs.y == rhs.y) && 
	(lhs.z == rhs.z) && 
	(lhs.w == rhs.w);
}
```
Разница между данными подходами кроется в понятиях равенства и эквивалентности.
## Равенство и эквивалентность
Базовая эквивалентность объектов означает что их адреса равны,
то есть **это буквально один и тот же объект**.

Равенство через operator== может работать столь угодно сложно
```cpp
bool operator== (const Foo& lhs, const Foo& rhs)
{
	bool res;
	std::cout << lhs << " vs " << rhs << "?" << std::endl;
	std::cin >> std::boolalpha >> res;
	return res;
}
```
Это конечно крайний случай, просить пользователя нам вот так вот 
помочь.

Считается, что хороший оператор равенства удовлетворяет трём основным
соотношениям:
```cpp
// рефлексивность
assert (a == a); 
// симметричность
assert ((a == b) == (b == a)));
// транзитивность
assert ((a != b) || ((a == b) && (b == c)) == (a == c));
```
Говорят, что отношения, которые обладают такими свойствами являются
**отношениями эквивалентности**.
## Дву и три валентные сравнения
В языке C приняты тривалентные сравнения
```c
strcmp(p, q); // returns -1,0,1
```
В языке C++ приняты двувалентные сравнения
```cpp
if (p > q)  // if (strcmp(p, q) == 1)
if (p >= q) // if (strcmp(p, q) == -1)
```

Кажется, что из одного тривалентного сравнения <=>
можно соорудить все двухвалентные.
