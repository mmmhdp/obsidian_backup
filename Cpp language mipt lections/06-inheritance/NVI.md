Non virtual interface - если таки хочется интерфейс с аргументами по умолчанию, его можно сделать невиртуальным, чтобы никто не смог их переопределить в классах наследниках:
```cpp
#include <iostream>

class Base {
  virtual int foo_impl(int x) { return x; };
public:
  int foo(int x = 52) { return foo_impl(x); };
};

class Derived : public Base {
  int foo_impl(int x = 13) override { return x * 2; };
  /*
  данный аргумент будет проигнорирован, вернее как
  раз трюк в том, что мы как раз к нему никогда не обратимся
  из-за наличия обёртки
  */
};

int main() {
  Base *pb = new Derived{};
  std::cout << pb->foo() << std::endl;
  // 106

  Derived *pd = static_cast<Derived *>(pb);
  std::cout << pd->foo() << std::endl;
  // 106
}
```
В итоге получаем, что закрытая виртуальная функция открыто переопределена. И это нормально, так как хоть функция и имеет private модификатор, она не перестаёт быть частью интерфейса класса, т.е. несмотря на то, что вызывать её из класса наследника нельзя, такого имени нет, попытка его найти провалится, переопределить её как виртуальную всё ещё можно, подстановка опирается просто на наличие для override функции с подходящей сигнатурой.


Важно, что тут мы видим, что override может влиять на модификатор видимости, в данном случае он сменился с private -> public.
