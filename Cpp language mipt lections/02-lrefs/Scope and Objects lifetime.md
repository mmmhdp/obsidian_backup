# `Scope`
У любого имени есть область видимости (`scope`): совокупность всех мест в программе, откуда к нему можно обратиться
```cpp
int a = 2;
void foo() { 
	int b = a + 3; 
	// ok, we are in scope of a 
	if (b > 5)  {
	 int c = (a + b) / 2; 
	 // ok we are in scope of a and b
	}
	b += c; 
	// compilation fail 
}
```
# `Lifetime` 
У любой переменной есть время жизни - это совокупность всего моментов времени в программе, когда её состояние валидно.

Первый такой момент случается после окончания инициализации
```cpp
int x = x; // переменная x объявлена, но время её жизни вообще-то ещё не началось, будет ошибка 
```

Использование до полной инициализации - редкость, а вот использование после смерти - явление очень частое, например вот [[Left reference#Dangling refs]].
# `Lifetime of temporary objects`
## **БАЗА: ВРЕМЕННЫЙ ОБЪЕКТ ЖИВЁТ ДО КОНЦА ПОЛНОГО ВЫРАЖЕНИЯ**

Тут начинается беда для ссылок, так как продление жизни [[Left reference#Lifetime extension]] продляет жизнь объекта, на который сделана константная ссылка, но продляет она её только для того, который был тут же при её создании инициализирован (собсвенно, иначе и быть не может, это же ссылка на неизменяемый объект).

Вот пример, где уловить разницу становится сложно
```cpp
struct S {
	int x;
	const int &y;
};

S x{1,2};
/*
	ok, for y will extend lifetime of inner int object = 2, 
	x here is not temporary, 
	subobject of x - y - helds temporary object 
	with prolonged lifetime
*/

S *p = new S{1,2}; 
// here we have dangling y after end of expression 

/*
	the problem is that here 
	we not initialize subobject itself, 
	we initialize value of p - 
	pointer to some unnamed object, 
	constructed from temporary object S{1,2}.
	So p.y is invalid here.
*/

```
Т.е. тут во втором случае временный объект (`S[1,2]`), продлявший жизнь константе, сам закончил своё существование под конец полного выражения. Да, из него через оператор `new` действительно был создан новый объект, но мы ссылку то связали с этим, который уже помрет в конце полного выражения.

Занятный вывод из примера - класс с полем, который является левой ссылкой - скорее всего очень плохая идея.
## Иногда временный объект не создаётся
Неконстантные левые ссылки не создают временных объектов и просто отказываются связываться с литералами:
```cpp
int foo(int &x);

foo(1); // ошибка компиляции
```
И даже проще:
```cpp
int &x = 1; // тоже ошибка компиляции
```
